# endstone-status-api v0.1.2

Fix a production-observed error when malformed HTTP request lines cause Python's `BaseHTTPRequestHandler` to call `send_error()` before initializing request headers. StatusApi now avoids reading `self.headers` in that state, returning the intended `400` problem response instead of raising `AttributeError`.

Two real-socket regression cases cover invalid HTTP/0.9 request types and invalid HTTP versions; both assert continued successful handling of a subsequent normal request. Regular CORS behavior and API v1 responses are unchanged.

Upgrade the wheel in Endstone's Python environment and restart Endstone. No configuration migration or new dependency is required.
